어제 트랜지스터 하나가 전압으로 켜고 끄는 스위치라는 것까지 봤다. 오늘은 그 스위치를 엮어서 계산기를 만들고, 그 계산기를 어디에 얼마나 깔았는지로 CPU와 GPU를 구분하는 데까지 왔다.

## 거꾸로 켜지는 쌍둥이, pMOS

어제 배운 트랜지스터는 정확히는 nMOS였다. 게이트에 1V를 걸면 실리콘 표면에 전자가 모여서 통로가 생기는 것. 오늘 알게 된 건 그 반대로 동작하는 pMOS가 있다는 것이다.

| 게이트 전압 | nMOS | pMOS |
|---|---|---|
| 1V | 켜짐 | 꺼짐 |
| 0V | 꺼짐 | 켜짐 |

차이는 실리콘에 섞은 불순물이 반대라는 것이다. nMOS는 게이트가 전자를 끌어와서 전자 다리를 만들고, pMOS는 게이트가 전자를 밀어내서 전자가 빠진 자리로 다리를 만든다. 빈자리로 전류가 흐른다는 게 안 와닿았는데, 주차장에서 차가 왼쪽으로 한 칸씩 가면 빈자리가 오른쪽으로 가는 것처럼 보이는 것과 같다고 한다. 움직이는 건 여전히 전자다.

```
빈자리가 오른쪽으로 이동 = 차들이 왼쪽으로 한 칸씩 이동

시각 1:  [차][차][  ][차][차]
시각 2:  [차][차][차][  ][차]
시각 3:  [차][차][차][차][  ]
```

## 트랜지스터는 판단하지 않는다

nMOS와 pMOS를 이렇게 묶으면 NOT 게이트가 된다. 입력 하나가 두 게이트에 동시에 걸린다.

```
            전원선 1V
               |
      +------[pMOS]
      |        |
입력 -+        +-------- 출력
      |        |
      +------[nMOS]
               |
             접지선 0V
```

입력이 1V면 nMOS가 켜져서 출력이 접지선에 붙어 0V. 입력이 0V면 pMOS가 켜져서 출력이 전원선에 붙어 1V. 입력이 뒤집혀서 나온다.

처음에 "nMOS와 pMOS가 나란히 있으면 NOT을 판단하는 거냐"고 물었는데 틀린 질문이었다. 판단하는 부품은 없다. 반대로 반응하는 스위치 두 개를 같은 입력에 묶어 놓으니 항상 한쪽만 켜지고, 그래서 출력이 입력과 반대인 쪽 선에 붙는 것뿐이다. 시소 양 끝에 두 사람이 앉은 것과 같다. 앞으로 나오는 모든 게이트와 덧셈기, 곱셈기가 전부 이 원리다. 물리적인 그 상태가 곧 결과인 것이다. 

출력선에 대해서도 오해가 있었다. 접지선에 안 닿으면 디폴트로 1V인 줄 알았는데, 출력선은 그냥 도선이라 디폴트 전압이 없다. 전원선에 붙으면 1V, 접지선에 붙으면 0V, 어디에도 안 붙으면 값이 정해지지 않고 떠 버린다. 그래서 nMOS와 pMOS를 꼭 쌍으로 쓴다. 한쪽은 0을 만들고 한쪽은 1을 만들어야 출력이 떠 있는 순간이 없다. 칩 안의 모든 1V는 전원선에서, 모든 0V는 접지선에서 온다. 입력선은 앞 게이트의 출력선이고, 중간 게이트들은 어느 도선을 어느 선에 붙일지만 바꿔 준다.

## NAND는 4개, AND는 6개

입력이 두 개인 게이트 중 CMOS에서 가장 만들기 쉬운 건 AND가 아니라 NAND다. 둘 다 1일 때만 0, 나머지는 1. nMOS 둘을 직렬로 놓으면 둘 다 켜져야 접지까지 뚫리고, pMOS 둘을 병렬로 놓으면 하나만 켜져도 전원선에 붙는다.

```
              전원선 1V
            +-----+-----+
입력 A ---[pMOS A]  [pMOS B]--- 입력 B
            +-----+-----+
                  |
                  +--------- 출력
                  |
입력 A --------[nMOS A]
                  |
입력 B --------[nMOS B]
                  |
                접지선 0V
```

네 경우를 손으로 다 따라가 봤다. 결론은 맞았는데 중간에 nMOS와 pMOS의 켜짐 꺼짐을 전부 거꾸로 적은 적이 있다. A와 B가 대칭이라 우연히 답이 맞은 거였다. nMOS는 어제 그 트랜지스터라 1V에 켜지고, pMOS는 그 반대. 이걸 확실히 잡고 나서야 (1,1)일 때 pMOS 둘 꺼짐, nMOS 둘 켜짐, 출력 0V가 제대로 나왔다.

| 게이트 | 트랜지스터 수 |
|---|---|
| NOT | 2 |
| NAND | 4 |
| AND | 6 (NAND + NOT) |

AND가 NAND보다 비싸다. 뒤집힌 걸 다시 뒤집어야 하니까. 그래서 실제 칩에서는 NAND를 훨씬 많이 쓴다고 한다.

## 덧셈기, 곱셈기, 그리고 MAC

1비트 두 개를 더하면 1+1에서 자리올림이 생긴다. 그래서 출력이 둘이다. 자리올림(Carry)은 둘 다 1일 때만 1이니 AND, 그 자리 합(Sum)은 둘이 다를 때만 1이니 XOR. 게이트 두 개로 반가산기가 된다. 여러 자리를 더하려면 아래 자리에서 올라온 Carry까지 셋을 더해야 해서 전가산기가 필요하고, 트랜지스터 40개 안팎이다.

전가산기를 자리 수만큼 늘어세우고 Carry를 윗자리로 넘기면 여러 자리 덧셈기다.

```
  A3 B3       A2 B2       A1 B1       A0 B0
   |  |        |  |        |  |        |  |
 [전가산기]<-[전가산기]<-[전가산기]<-[전가산기]<- 0
   |  C3       |  C2       |  C1       |
   S3          S2          S1          S0
```

맨 오른쪽의 0은 아래 자리가 없으니 Carry 입력을 접지선에 묶어 0으로 고정한 것이다. 비워 두면 전압이 떠 버리니까.

여기서 어제 배운 클록이 바로 나온다. 맨 윗자리 결과는 Carry가 모든 자리를 다 통과한 뒤에야 확정된다. 이게 어제 말한 사슬 길이다. 덧셈기가 길수록 클록을 느리게 해야 하고, 빠른 CPU는 Carry를 미리 예측하는 복잡한 덧셈기를 써서 트랜지스터를 더 쓰는 대신 사슬을 짧게 만든다. 속도와 트랜지스터 수를 맞바꾸는 것이다.

곱셈은 이진수라 쉽다. 곱하는 자리가 1이면 그대로 옮겨 쓰고 0이면 전부 0이다. 구구단이 없다. 부분 곱 한 칸이 AND 하나고, 그 줄들을 덧셈기로 더하면 끝이다. 곱셈기 = AND 격자 + 덧셈기 여러 층. 새 부품은 없다.

곱한 값을 이전 합에 계속 더해 쌓는 블록이 MAC(Multiply-Accumulate)이다. 곱셈기 뒤에 덧셈기와 레지스터가 하나씩 더 붙는다. AI 연산은 거의 전부 a1×w1 + a2×w2 + ... 모양이라 이 블록이 핵심이다.

| 블록 | 트랜지스터 (대략) |
|---|---|
| 8비트 곱셈기 | 2,500~3,000 |
| 8비트 MAC | 3,000~4,000 |

처음에 "3×3 계산에 MAC 3~4천 개가 필요한 거냐"고 물었는데 단위가 섞인 거였다. 숫자 둘을 한 번 곱하는 건 MAC 하나가 1클록에 하는 일이고, 그 MAC 하나가 트랜지스터 3~4천 개다. CPU 코어 하나가 수억 개니까, 그 면적에 MAC을 수만 개 깔 수 있다는 뜻이다. 어제 "차이는 트랜지스터를 어디에 배분했나"라고 한 말이 여기서 숫자로 바뀐다.

사양서의 TOPS는 MAC 수에 클록을 곱한 것이다. MAC 하나가 1클록에 곱셈과 덧셈 두 번을 하니까 TOPS ≈ MAC 수 × 클록(GHz) × 2 ÷ 1000. 거꾸로 TOPS를 보면 MAC이 몇 개 깔렸는지 역산할 수 있다. 카메라에 들어가는 NPU는 수 TOPS, 스마트폰과 노트북은 수십, 데이터센터는 수백 이상이다. 다만 희소 기준인지, INT8인지 INT4인지, 피크인지 실제인지에 따라 같은 숫자가 2~3배 다른 성능을 뜻할 수 있다.

## 네 칩을 구분하는 틀

트랜지스터를 어디에 썼나. 쓸 곳은 네 가지다. 연산기, 제어기, 캐시, 데이터 이동.

```
CPU 코어 하나          GPU                  NPU / TPU
+----------------+    +----------------+    +----------------+
|  제어  제어    |    | 제어 | 연산 연산 |    | 연산 연산 연산 |
|  제어  제어    |    |------+ 연산 연산 |    | 연산 연산 연산 |
|----------------|    | 제어 | 연산 연산 |    | 연산 연산 연산 |
|  캐시  캐시    |    |------+ 연산 연산 |    |----------------|
|  캐시  캐시    |    | 캐시 | 연산 연산 |    | 큰 내부 메모리  |
|----------------|    +----------------+    +----------------+
|  연산 (작음)    |
+----------------+
```

연산기는 지금까지 만든 것들이다. 덧셈기, 곱셈기, MAC, 비교기를 한 묶음으로 모은 회로. 값 두 개를 받아 결과를 내는 것만 한다. 어느 걸 쓸지, 어떤 값을 받을지, 결과를 어디에 둘지는 스스로 못 정한다.

제어기는 그걸 정하는 회로다. 명령 한 줄을 읽고 해독해서 "레지스터 a와 b를 열어라, 덧셈기를 써라, 결과는 x에 넣어라, 다음은 몇 번째 줄"이라는 신호를 뿌린다.

## CPU는 왜 제어가 뚱뚱한가

CPU가 하는 일은 다음 명령 하나를 가능한 한 빨리 끝내는 것이다. 프로그램은 한 줄씩 앞줄 결과에 의존한다. 그래서 두 가지가 괴롭다.

다음에 뭘 할지 미리 모른다. 조건문은 앞 계산이 끝나야 어느 줄로 갈지 정해진다. 기다리면 연산기가 노니까 "아마 이쪽일 것이다"라고 찍어서 먼저 시작한다. 분기 예측이다. 맞을 확률을 높이려고 과거 기록을 저장하고 비교하는 회로가 붙는다.

데이터가 멀리 있다. 메인 메모리에서 값을 가져오는 데 수백 클록이 걸리는데 덧셈은 1클록이다. 그래서 최근 쓴 데이터를 칩 안에 복사해 두는 캐시를 크게 둔다. 캐시는 어제 배운 레지스터 같은 회로가 수백만 개 모인 거라 면적을 엄청 먹는다.

결과적으로 CPU 코어에서 실제로 곱하고 더하는 부분은 한 자리 퍼센트다. 나머지는 그 연산기를 쉬지 않게 하는 장치다.

그런데 AI 연산은 성격이 다르다. a1×w1 + a2×w2 + ... 는 분기가 없고, 곱셈끼리 서로 의존하지 않고, 데이터가 어디 있는지 미리 안다. CPU가 면적의 대부분을 쓴 장치가 거의 전부 쓸모가 없다. 그 면적을 떼어 내고 MAC으로 채우면 GPU, 더 극단으로 가면 NPU와 TPU다.

## NPU의 MAC은 언제 노나

"순차적으로 층을 곱해야 할 때, 제어기가 없어서 다음 단계를 못 준비하니까 노는 것 아닌가" 했는데 핵심이 아니었다. 한 층 안에 곱셈이 수백만 개라 층 경계에서 몇 클록 노는 건 미미하다. 그리고 NPU에도 미리 정해진 순서를 따라가는 단순한 순서기는 있다. 없는 건 매 명령마다 판단하는 장치다. 순서를 모르는 게 아니라 전부 미리 알아서 예측이 필요 없는 것이다.

실제로 MAC을 놀게 하는 건 세 가지다.

- 메모리에서 들어오는 길이 좁아서 MAC이 값을 기다릴 때. MAC을 더 깔아도 길이 안 넓어지면 TOPS만 오르고 속도는 안 오른다.
- MAC 격자보다 행렬이 작아서 격자의 대부분이 빌 때.
- NPU가 모르는 연산자가 나와서 그 부분을 CPU에 넘길 때. 그동안 MAC 전체가 놀고 데이터 왕복 비용까지 든다.

전부 "제어가 없어서"가 아니라 "제어를 없애고 MAC을 꽉 채운 대가"다.

## GPU: 제어기 하나를 32개가 나눠 쓴다

GPU는 연산기 수천 개를 깔되, 작은 제어기를 묶음마다 하나씩 남겨 둔 구조다. 제어기 하나가 연산기 32개에 같은 신호를 뿌린다.

```
                 [제어기 하나] --"지금 덧셈"-->
                 /      |      |      \
          [연산기1] [연산기2] [연산기3] ... [연산기32]
           a1+b1    a2+b2    a3+b3        a32+b32
```

"32개가 서로 다른 일을 할 수 있지 않을까" 했는데 안 된다. 제어기가 한 클록에 명령 하나만 해독하니 32개는 같은 클록에 반드시 같은 연산을 한다. 다른 건 값뿐이다. CPU식 사고였다. CPU는 코어마다 제어기가 있어서 서로 다른 일을 하고, GPU는 제어기를 나눠 쓰는 대신 그 면적에 연산기를 더 넣은 것이다.

그러면 조건문을 만나 32개 중 일부는 3번 줄, 일부는 5번 줄로 가야 하면 어떻게 되나. "제어기가 연산기 하나에만 판단을 시키나" 했는데 그것도 아니었다. 비교는 32개가 각자 자기 값으로 동시에 한다. 문제는 그 다음이다. 제어기가 두 줄을 동시에 뿌릴 수 없으니 두 길을 순서대로 둘 다 지나간다.

```
클록 t   : "3번 줄 실행"  [12개 실행] [20개 꺼 둠]
클록 t+1 : "5번 줄 실행"  [12개 꺼 둠] [20개 실행]
클록 t+2 : 합류, 32개 모두 다음 줄
```

길이 둘이면 시간 2배, 활용은 절반. 분기 발산이라고 한다. 합성곱과 행렬 곱은 조건문이 없어서 GPU가 꽉 차서 돈다. 검출 후처리처럼 "이 상자가 저 상자와 겹치면 버린다" 같은 조건이 데이터마다 갈리는 단계는 GPU에서 효율이 떨어진다. 모델은 빠른데 전체 FPS가 안 나오는 상황의 상당수가 여기서 생긴다고 한다.

## 오늘까지 정리

| | 제어기 | 연산기 | 잘하는 것 | 약한 것 |
|---|---|---|---|---|
| CPU | 코어마다 하나, 매우 똑똑함 | 코어당 몇 개 | 한 줄씩 의존하는 일, 분기 많은 일 | 같은 연산 수백만 번 |
| GPU | 32개가 하나 공유, 단순함 | 수천 개 | 같은 연산을 다른 값으로 대량 | 데이터마다 길이 갈리는 일 |

NPU와 TPU는 여기서 한 발 더 나간다. 제어기를 더 줄이고, 연산기를 MAC으로 고정하고, MAC끼리 직접 값을 넘겨서 메모리 왕복을 줄인다. 그 구조는 다음에 본다.
