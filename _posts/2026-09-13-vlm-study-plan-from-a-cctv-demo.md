회사에서 VLM 관련 업무를 하다 보니 자꾸 관심이 간다. 좀 더 깊이 공부해보고 싶어서 AI 선생님에게 학습 순서와 읽어볼 자료, 영상 목록을 받았다.

8주 동안 공부하는 계획이라는데, 얼마나 유용할지 실제로 공부해보려고 한다.

## 얼마나 걸릴까

- **기본 계획은 8주, 주당 10시간, 총 80시간이다.**
- 영상 재생 시간의 합이 아니라 읽기, 다시 보기, 코드 확인, 실험, 기록과 리뷰 준비를 포함한 예상 시간이다.
- 영어 자료와 수학 복습에 시간이 더 필요하면 10~12주까지 늘려 잡는다.
- 첫 4주, 약 40시간은 VLM의 구조와 핵심 개념을 이해하는 구간이다.
- 다음 4주, 약 40시간은 그 개념을 데모의 입력 설계, 평가, 속도 문제에 적용하는 구간이다.
- 8주 뒤 목표는 VLM 연구를 모두 이해하는 것이 아니다. **내 데모의 흐름을 설명하고, 개선 가설을 세우고, 비교 실험의 결과와 한계를 설명할 수 있는 수준**을 목표로 한다.

| 우선순위 | 기간 | 주제 | 예상 시간 |
|---|---|---|---|
| 1 | 1주 차 | VLM 전체 구조와 학습·추론의 차이 | 10시간 |
| 2 | 2주 차 | 토큰, 임베딩, 벡터와 행렬 | 10시간 |
| 3 | 3주 차 | 어텐션과 답변 생성 | 10시간 |
| 4 | 4주 차 | 이미지 패치와 영상 입력 | 10시간 |
| 5 | 5~6주 차 | 질문·판정 설계와 성능 평가 | 20시간 |
| 6 | 7~8주 차 | CPU 추론, 캐시와 통합 실험 | 20시간 |

## 1순위: VLM의 전체 지도부터 보기 — 1주 차

- **핵심 질문:** 이미지를 넣으면 어떤 과정을 거쳐 문장이 나올까?
- 공부할 개념:
  - 시각 인코더: 이미지에서 특징을 추출하는 부분.
  - 프로젝터 또는 연결 모듈: 시각 표현을 언어 모델이 받아들일 수 있도록 연결하는 부분.
  - 언어 모델: 이미지 정보와 질문을 이용해 답변을 생성하는 부분.
  - 학습과 추론: 모델의 파라미터를 바꾸는 과정과, 학습된 모델을 사용하는 과정의 차이.
- 먼저 읽을 자료: [Hugging Face — Vision Language Models Explained](https://huggingface.co/blog/vlms).
  - `What is a Vision Language Model?`과 `Technical Details`부터 읽는다.
  - 대표적인 구조를 이해하는 용도로 읽는다. 모든 VLM이 같은 구조인 것은 아니다.
  - 2024년 글이므로 당시 모델 순위와 설치 코드는 이번 공부의 중심에서 뺀다.
- 연결할 논문: [Visual Instruction Tuning — LLaVA](https://arxiv.org/abs/2304.08485).
  - 구조 그림과 학습 단계 설명만 읽는다.
  - 사전학습된 시각 모델과 언어 모델을 어떻게 연결하고 지시문에 답하도록 학습시키는지 살펴본다.
- 해볼 일:
  - `영상 → 프레임 선택 → 이미지 구성 → VLM 질문 → 응답 처리 → 규칙 판정`을 그린다.
  - 그중 VLM 내부를 시각 인코더, 연결 모듈, 언어 모델로 펼쳐본다.
- 완료 기준: 그림을 보며 각 부분의 역할과, 내가 바꾸는 부분이 어디인지 5분 안에 설명한다.

## 2순위: 임베딩을 수학적으로 이해하기 — 2주 차

- **핵심 질문:** 단어나 이미지가 숫자 벡터가 된다는 것은 무슨 뜻일까?
- 공부할 개념: 토큰, 임베딩, 벡터의 차원, 내적, 행렬 곱, 코사인 유사도.
- 먼저 볼 영상·글:
  - [3Blue1Brown — Transformers, the tech behind LLMs](https://www.3blue1brown.com/lessons/gpt/): 전체 흐름을 본 뒤 임베딩 부분을 다시 본다.
  - [3Blue1Brown — Dot products and duality](https://www.3blue1brown.com/lessons/dot-products/): 내적 계산과 기하학적 의미를 연결한다.
- 해볼 일:
  - 숫자 세 개짜리 벡터 두 개로 내적을 직접 계산한다.
  - 한 벡터를 두 배로 늘렸을 때 내적과 코사인 유사도가 어떻게 달라지는지 비교한다.
  - 작은 행렬에 벡터를 곱해 새로운 벡터가 만들어지는 과정을 확인한다. 스프레드시트로 해도 된다.
- 주의할 점:
  - 임베딩의 각 좌표가 사람이 붙인 속성 하나씩에 대응한다고 가정하지 않는다.
  - 언어 모델 내부의 토큰 표현과 검색용 문장·이미지 임베딩은 용도와 만드는 방식이 다를 수 있다.
- 완료 기준: 벡터의 크기, 방향, 변환을 구분하고 임베딩이 왜 단순한 이름표보다 많은 정보를 담을 수 있는지 설명한다.

### 임베딩과 인덱싱은 구분하기

- 임베딩은 정보를 벡터로 표현하는 것이다.
- 벡터 검색용 인덱싱은 그 벡터들 중 가까운 것을 효율적으로 찾도록 구성하는 것이다. [Faiss 공식 설명](https://github.com/facebookresearch/faiss/wiki)
- 지금의 질문·판정 데모에서는 임베딩의 기초를 먼저 공부한다.
- 인덱싱은 나중에 “비슷한 과거 CCTV 장면을 검색하자”라는 문제가 생기면 이어서 공부한다.

## 3순위: 어텐션과 답변 생성 이해하기 — 3주 차

- **핵심 질문:** 같은 이미지인데 질문이 바뀌면 답이 왜 달라질 수 있을까?
- 공부할 개념: 문맥에 따른 표현 변화, Query·Key·Value, 가중합, softmax, 다음 토큰 예측.
- 볼 영상: [3Blue1Brown — Attention in transformers, step-by-step](https://www.youtube.com/watch?v=eMlx5fFNoYc).
  - 다시 읽을 때는 [같은 내용의 글](https://www.3blue1brown.com/lessons/attention/)을 활용한다.
  - 처음에는 관련도를 계산하고, 가중치로 바꾸고, 정보를 가중합하는 흐름에 집중한다.
- 해볼 일:
  - 세 항목에 서로 다른 가중치를 주고 가중합을 계산한다.
  - 같은 이미지에 질문 표현을 두 가지로 바꾸되 다른 설정은 고정한다.
  - 답변이 달라진 사례와 그대로인 사례를 각각 기록한다.
- 주의할 점:
  - 어텐션의 구조를 이해한 것과 특정 오답의 원인을 입증한 것은 다르다.
  - 모델이 생성한 설명도 실제 내부 판단 과정을 그대로 보여주는 증거로 취급하지 않는다.
- 완료 기준: 입력 문맥이 답변 생성에 영향을 주는 흐름을 설명하되, 실험으로 확인하지 않은 원인은 가설로 남긴다.

## 4순위: 이미지 패치와 영상 입력 이해하기 — 4주 차

- **핵심 질문:** 사람을 크롭하면 왜 안전모 판정이 달라질까? 두 시점을 붙인 이미지는 영상 입력과 어떻게 다를까?
- 공부할 개념: 리사이즈, 이미지 패치, 시각 토큰, 동적 해상도, 프레임 샘플링, 시간 정보.
- 읽을 자료:
  - [An Image Is Worth 16×16 Words — ViT](https://arxiv.org/abs/2010.11929): Figure 1과 패치를 입력으로 만드는 설명.
  - [Qwen2.5-VL 공식 블로그](https://qwenlm.github.io/blog/qwen2.5-vl/): 이미지·영상 처리 방식의 큰 흐름.
  - [Qwen2.5-VL Technical Report](https://arxiv.org/abs/2502.13923): 해상도와 시간 정보 처리에 해당하는 부분.
- 해볼 일:
  - 성공·실패 사례 10~20개를 골라 전체 화면과 사람 크롭을 비교한다.
  - 가능한 경우 실제 전처리 후 이미지를 확인하고 안전모가 얼마나 크게 남는지 기록한다.
  - 두 시점을 붙인 한 장과 각 시점의 단일 이미지에서 오류가 어떻게 다른지 비교한다.
- 주의할 점:
  - 크롭 후 확대가 원본에 없는 세부 정보를 복원하는 것은 아니다.
  - 모델 자체의 영상 지원과 현재 실행 환경에서 실제 사용하는 입력 방식은 따로 확인한다.
- 완료 기준: 모델이 필요한 시각 정보를 받았는지와, 받은 정보를 잘 판단했는지를 구분해서 질문할 수 있다.

## 5순위: 질문·판정 설계와 평가 — 5~6주 차

- **핵심 질문:** 정확도가 올랐다는 것을 어떻게 확인하고, 어느 오류를 줄여야 할까?
- 공부할 개념:
  - 사람별 속성과 장면 전체의 판정.
  - AND·OR, “한 명이라도”와 “모든 사람”의 차이.
  - 미착용과 관찰 불가능의 구분.
  - 혼동 행렬, precision, recall, 개발용·평가용 데이터 분리.
- 읽을 자료:
  - [scikit-learn 평가 지표 설명](https://scikit-learn.org/stable/modules/model_evaluation.html): 혼동 행렬, precision, recall 부분.
  - [GroupKFold 설명](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GroupKFold.html): 같은 그룹을 평가 양쪽에 섞지 않는 개념.
- 5주 차에 해볼 일:
  - 사람이 두 명인 장면을 골라 각 사람을 따로 잘라 질문한다.
  - 사람 A의 안전모와 사람 B의 조끼를 한 사람의 조건처럼 합치지 않는지 확인한다.
  - 모델의 관찰 결과와 코드의 최종 판단을 분리해서 기록한다.
- 6주 차에 해볼 일:
  - 경보를 양성으로 정하고, 헛알람과 놓친 알람을 직접 센다.
  - 녹화 단위로 개발용과 최종 평가용을 나누는 방법을 연구소와 정한다.
  - 이미 반복해서 본 자료의 평가 한계를 기록하고, 가능하면 새로운 녹화를 최종 확인용으로 확보한다.
  - 정답표 버전, 판정 불가 사례 수, 지표의 분모를 함께 적는다.
- 완료 기준: “정확도 몇 퍼센트”에 더해 어느 조건에서 어떤 오류가 발생했고, 다른 영상에서도 유지되는지 어디까지 확인했는지 설명한다.

## 6순위: CPU 추론과 캐시, 통합 실험 — 7~8주 차

- **핵심 질문:** 왜 느리고, 어떤 계산을 재사용했을 때 빨라질까?
- 공부할 개념: 양자화, 이미지 인코딩, 입력 처리(prefill), 토큰 생성(decode), KV 캐시, 캐시가 비어 있거나 준비된 상태의 차이.
- 읽을 자료: [llama.cpp 서버 공식 문서](https://github.com/ggml-org/llama.cpp/tree/master/tools/server).
  - 연구소와 함께 사용 중인 버전에 해당하는 설정과 로그를 확인한다.
  - 문서 전체보다 현재 실행 명령과 캐시·시간 측정 항목에 집중한다.
- 7주 차에 해볼 일:
  - 완전히 같은 입력의 반복, 같은 이미지에 다른 질문, 다른 이미지의 세 경우를 나눠 측정한다.
  - 서버를 새로 시작했을 때와 반복 실행했을 때를 구분한다.
  - 호출 순서와 입력 크기를 기록하고, 속도와 답변을 함께 비교한다.
  - 로그의 유사도 값이 무엇을 비교하는지 확인한다. 이름만 보고 이미지의 시각적 유사도라고 단정하지 않는다.
- 8주 차에 해볼 일:
  - 지금까지 배운 것 중 개선 가설 하나를 고른다.
  - 기준 설정과 변경 설정을 비교하고 정확도·오류 종류·지연을 함께 정리한다.
  - 최종 평가 전에 설정을 고정하고, 평가 결과를 본 뒤 바꾼 내용은 추가 개발로 구분한다.
- 완료 기준: 빨라졌다는 관측과 그 원인에 대한 설명을 분리하고, 다른 환경에서도 같은 효과가 날지 확인할 조건을 말할 수 있다.

## 격주 리뷰에는 무엇을 가져갈까

| 리뷰 | 가져갈 결과 | 검토받을 질문 |
|---|---|---|
| 시작 전 | 현재 데모 흐름과 대표 실패 사례 | 내가 이해한 구조가 맞는가? |
| 2주 후 | 구조 그림과 임베딩 기초 정리 | 모델 내부 표현과 검색용 임베딩을 제대로 구분했는가? |
| 4주 후 | 질문·크롭·입력 비교 | 이 실험으로 원인 가설을 구분할 수 있는가? |
| 6주 후 | 오류 표와 데이터 분리 계획 | 개선됐다고 판단할 평가 방법인가? |
| 8주 후 | 정확도와 지연을 포함한 최종 비교 | 어떤 조건에서 쓸 수 있고 무엇을 더 확인해야 하는가? |

## 공부가 끝없이 늘어나지 않도록

- 논문은 먼저 초록, 구조 그림, 이번 질문에 해당하는 부분만 읽는다.
- 영상과 글을 본 뒤에는 내 데모에 연결되는 설명이나 실험을 하나 남긴다.
- Python은 데모의 이미지 처리, 모델 요청, 결과 저장, 채점 코드를 따라 읽는 데 필요한 만큼 함께 배운다.
- 모델을 처음부터 학습시키기, 전체 미적분 복습, 벡터 데이터베이스 구축은 이번 8주의 필수 범위에 넣지 않는다.
- 매번 기록을 세 가지로 나눈다: **직접 관측한 사실 / 원인에 대한 가설 / 아직 확인하지 못한 것.**
- 더 궁금한 질문은 별도 목록에 남긴다. 이번 실험의 결과를 설명할 만큼 이해했다면 다음 단계로 넘어간다.

공부의 단위는 자료 한 편을 끝내는 것이 아니라, 데모에 관한 질문 하나를 더 정확하게 설명할 수 있게 되는 것으로 잡아보려 한다.
