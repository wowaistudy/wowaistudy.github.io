얼마 전 회사 동료에게 읽고 계신 기술블로그가 있냐고 물어봤더니, 기술블로그는 없는데 허깅페이스에 오늘의 논문이 있다는 사실을 알았다. 논문이 내가 읽어볼만한 수준인지 궁금해서 살펴봤는데, 그럭저럭 클로드와 함께 읽으니 읽어볼 만했다. 연결된 두 편이 있어서 읽어본 기록을 남긴다.

## 첫 번째: VLM 오답 노트

AgentVQA라는 논문이다. 요약하면 시험지 하나를 만들고, 모델 스물 몇 개에게 시험을 치게 하고, 틀린 답을 뜯어서 왜 틀렸는지 분류했다.

시험지가 좀 특이하다. 보통 VQA는 "사진에 뭐가 있나"를 묻는데, 이건 "이 화면에서 다음에 뭘 해야 하나"를 묻는다. 웹 화면에서 어느 버튼을 누를지, 로봇이 어느 물체를 집을지 같은 것이다. 논문은 이걸 agentic(에이전트형)이라고 부른다. 모델 종류가 아니라 과제 성격을 가리키는 말이었다.

오답 노트가 핵심이다.

```
틀린 이유                        
"문제를 잘못 읽었다"               드물다
"보고 나서 추론을 잘못했다"         드물다
"화면을 잘못 봤다"                 대부분
   - 눌러야 할 버튼 위치를 못 찾음
   - 물체들의 앞뒤·좌우를 헷갈림
   - 두 장면 사이에 뭐가 움직였는지 오인
```

모델은 뭘 해야 하는지는 알아듣는다. 그런데 지금 화면이 어떤 상태인지를 정확히 못 본다. 머리가 아니라 눈이 문제라는 결론이다. 1등 모델도 반 남짓밖에 못 맞혔다.

이게 남 얘기 같지 않았다. 특정 조건을 사진으로 판정하는 실험을 했을 때, 방 전체를 보내면 못 보던 걸 사람만 잘라서 보내니 보기 시작했고, 두 순간을 한 장에 붙여 보냈더니 같은 사람을 두 명으로 셌다. 그때는 작은 모델이라 그런 줄 알았는데, 이 논문을 보니 큰 모델도 똑같이 그런다. 모델을 키운다고 해결되는 문제가 아니라는 뜻이다.

여기서 "못 본다"는 말을 한 번 더 좁혀야 했다. 사진을 설명하라고 하면 잘한다. 그런데 "그래서 그게 어디 있나"를 물으면 틀린다. 장면을 말로 요약하는 능력과, 말과 화면 속 위치를 1대1로 묶는 능력은 다른 능력이었다. 논문은 뒤의 것을 grounding(접지)이라고 부른다.

## 두 번째: 손을 달아 준 모델

WeVisOne-VL이라는 논문이다. 첫 번째 논문이 진단이라면 이건 치료법이다. VLM이 설명만 하지 말고 박스도 치고 마스크도 그리게 만들었다.

마스크가 뭔지부터 몰랐다. 사진과 같은 크기의 0/1 지도다. 대상인 픽셀은 1, 아니면 0. 포토샵에서 누끼 따면 나오는 그것이다. 박스는 좌표 네 개라 네모 안에 배경이 섞이는데, 마스크는 사람 모양 그대로다. 개념 자체는 오래된 거고, 이 논문이 새로 한 건 "VLM 하나가 그걸 다 하게" 만든 것이다.

### 예전 방식

```
VLM         "흰 셔츠 사람: 박스 (120, 40, 310, 400)"    ← 글자로 숫자 네 개
   ↓
분할 모델    사진을 처음부터 다시 읽고, 박스 안을 0/1로 칠함
   ↓
매팅 모델    경계를 다듬음
```

모델 셋이 줄줄이다. VLM은 숫자만 말하고 그림은 다른 모델이 그린다. VLM이 박스를 조금 빗나가게 말하면 뒤는 그대로 믿고 엉뚱한 걸 뗀다.

VLM이 직접 못 그리는 이유가 있다. VLM의 출구는 토큰 하나다. 글자든 숫자든 한 번에 하나씩 나온다. 박스는 숫자 네 개라 이 출구로 나오는데, 마스크는 사진 크기만큼의 0과 1이라 글자로 쓰면 수십만 토큰이다. 출구가 너무 좁다.

### 이 논문 방식

출구 뒤를 뜯었다. 토큰이 나오기 직전에 모델 안에는 숫자 수천 개짜리 벡터가 있다. 그걸 사전과 대조해서 제일 가까운 글자 하나를 고른 게 토큰이다. 글자로 나오는 순간 수천 개 중 하나만 남고 나머지는 버려진다. hidden state(은닉 상태), 손글씨 실험 때 봤던 그 중간 값이다.

```
출구 직전 벡터   [0.5, 0.1, -0.3, 0.9, ...]   ← 수천 개, 정보가 많다
      ↓ 사전 대조
출력 토큰        <OBJ>                        ← 글자 하나, 정보가 거의 없다
```

VLM이 박스 좌표 뒤에 `<OBJ>`라는 토큰을 하나 더 뱉게 한다. 글자 `<OBJ>`는 아무 뜻이 없다. "여기 머릿속을 복사해 가라"는 표시다. 그 자리의 벡터를 버리지 않고 옆으로 빼서 작은 디코더에 준다.

그런데 벡터 하나로는 그림을 못 그린다. "저 사람"이라는 요약이지 픽셀 모양이 아니다. 그래서 디코더는 하나를 더 받는다. VLM이 사진을 읽을 때 ViT가 패치마다 만들어 둔 벡터들, feature map(특징 지도)이다. 사진 모양대로 놓인 격자다.

```
h  =  [0.5, 0.1, ...]        벡터 하나.  "누구를"
                                      
feature map                  격자.  칸마다 벡터 하나.  "어디서"
  ┌─────┬─────┬─────┐
  │ v11 │ v12 │ v13 │
  ├─────┼─────┼─────┤
  │ v21 │ v22 │ v23 │
  └─────┴─────┴─────┘

h · v11 = 0.1 → 0      h · v22 = 2.3 → 1      ← 칸마다 내적
```

h를 격자의 칸마다 내적한다. "이 칸이 저 사람과 얼마나 닮았나"를 칸 수만큼 잰다. 그 결과가 마스크다. 토큰으로는 못 뱉던 걸 내적으로 한 번에 펼친다.

feature map은 새로 계산하는 게 아니다. VLM이 사진을 읽으면서 어차피 만들어 둔 것이다. 그래서 디코더가 작다. 별도 분할 모델이 사진을 처음부터 다시 읽던 것과 여기가 다르다.

## 둘을 붙이면

첫 논문은 "VLM이 말은 하는데 가리키지 못한다"이고, 둘째 논문은 "가리키는 순간의 머릿속을 꺼내서 손을 달아 줬다"이다.

그리고 둘째 논문에서 systolic array 생각이 났다. 계산 결과를 메모리에 썼다 읽는 대신 옆 칸으로 바로 넘기는 게 systolic array였다. 여기서는 글자로 내보냈다가 다른 모델이 다시 읽는 대신, 내부 벡터를 바로 넘긴다. 좁은 통로가 메모리 버스냐 글자 출력이냐만 다르고, "좁은 형식으로 압축했다가 다시 펼치지 말고 풍부한 상태로 바로 넘겨라"는 같다. 같은 사진에 두 번 물으면 두 번째가 빨랐던 KV cache도 같은 원리다. 이미 계산한 걸 버리지 않는다.

## 아직 모르는 것

- `<OBJ>` 자리의 벡터가 처음부터 모양 정보를 담고 있던 건 아니다. 디코더를 붙여 학습시키니까 그 자리에 모양 정보를 담도록 VLM이 바뀐 것이라는데, 학습이 hidden state의 쓰임새를 정한다는 게 아직 감으로만 와 있다.
- 중간에서 벡터가 어떻게 바뀌는지, 특히 사진과 질문이 어떻게 섞이는지는 attention인데, 아직 안 했다. 오늘은 "중간에서 많이 계산해서 유용한 숫자 묶음이 된다"까지만 알고 읽었다.
- 첫 논문에서 "긴 추론을 켜면 인식 과제가 오히려 나빠지는 모델이 있다"고 했는데, 왜 그런지 설명이 없었다.

논문 하나 읽는 데 하루가 갔다. 그래도 벤치마크 논문부터 읽은 건 잘한 것 같다. 수식이 없어서 겁을 안 먹었다.
