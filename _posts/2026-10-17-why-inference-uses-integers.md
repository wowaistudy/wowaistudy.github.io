CPU, GPU, NPU, TPU 시리즈를 하다가 옆길로 빠진 내용인데, 실무에서 "양자화"라는 말을 자주 들었던 터라 따로 적어 둔다. 학습은 소수가 필요하고 추론은 정수로 충분하다는 말을 들었는데, 소수가 필요한 건 알겠고 추론이 왜 정수로 되는지가 안 왔다.

## 추론도 원래는 소수다

학습이 끝난 가중치는 0.0372, -0.0081 같은 소수다. 추론할 때는 이걸 정수로 바꿔서 쓴다. 이 변환이 양자화다. 방법은 그 층의 가중치 범위를 보고 -128~127로 나눠 쓰는 것이다.

```
이 층의 가중치 범위: -0.5 ~ +0.5
눈금 하나 = 0.5 ÷ 127 ≈ 0.0039

원래 소수      정수로
0.0372   →   0.0372 ÷ 0.0039 ≈ 9.5  →  10
-0.0081  →   -0.0081 ÷ 0.0039 ≈ -2.1 →  -2
0.4100   →   105
```

"눈금 하나가 0.0039"라는 숫자만 따로 기억해 두고, 계산은 정수로 하고 마지막에 한 번 곱해서 되돌린다. 입력 픽셀도 같은 식으로 정수로 바꾼다. 그러면 MAC을 지나가는 건 전부 정수다.

## 왜 값이 틀어져도 결과가 안 바뀌나

이유는 두 개다.

첫째, 추론이 마지막에 원하는 건 순위다. 사람 점수 8.3, 차 점수 2.1이면 사람이다. 반올림으로 8.1과 2.3이 되어도 답은 같다. 여기서 순위가 안 바뀐다는 건 가중치가 아니라 출력 점수 이야기다. 가중치는 반올림으로 조금씩 다 틀어진다. 그 가중치로 계산한 마지막 점수의 1등이 안 바뀐다는 뜻이다. 

둘째, 상쇄다. 반올림 오차가 수천 개 MAC을 지나며 쌓이지만 어떤 건 +로 어떤 건 -로 반올림되어서 서로 지워지는 쪽으로 간다.

## 왜 학습은 안 되나

학습은 가중치를 "0.0001만큼 줄여라" 같은 아주 작은 걸음으로 수만 번 고친다. 위 눈금에서 0.0001은 0.03칸이다. 반올림하면 0이다. 고치라는 명령이 전부 0으로 사라져서 수만 번 걸어도 가중치가 한 칸도 안 움직인다.

그러니까 "학습은 소수가 필요하다"는 말의 정확한 뜻은 "값이 소수라서"가 아니라 "눈금보다 작은 변화를 쌓아야 해서"다.

## 비트가 뭔지부터

여기서 비트가 뭔지 다시 물었다. 비트는 전선 한 가닥이다. 1V 아니면 0V, 그래서 1 아니면 0. 가닥을 늘리면 조합이 는다.

```
1비트 (전선 1가닥)  : 0, 1                   → 2가지
2비트              : 00, 01, 10, 11          → 4가지
8비트 (전선 8가닥)  : 00000000 ~ 11111111     → 256가지
32비트             :                         → 약 43억 가지
```

INT8은 전선 8가닥으로 정수 하나를 나른다는 뜻이고 그래서 256칸이다. INT4는 4가닥, 16칸. FP32는 32가닥으로 소수를 담는다.

```
INT8 눈금:  |·|·|·|·|·|·|·|·|·|·|·|·|·|·|·|·|·|·|·|·|·|·|·|·|·|·|·|·|·|·|·|·|  (256칸)
INT4 눈금:  |·······|·······|·······|·······|·······|·······|·······|·······|  (16칸)
```

## 정수로 하면 MAC이 작아진다

처음에 "정수로 하면 MAC 수요가 줄어드나" 했는데 그게 아니라 MAC 하나가 작아진다. 곱셈 횟수는 그대로다. 곱셈기 하나에 드는 트랜지스터가 줄어서 같은 면적에 MAC을 더 깔 수 있다.

작아지는 이유는 두 가지다. 하나는 곱셈기, 하나는 덧셈기 쪽인데 

첫째는 비트 수 자체다. 곱셈기는 A의 각 가닥 × B의 각 가닥을 전부 AND로 구한 뒤 더하는 구조라서 크기가 비트 수의 제곱이다. 8가닥씩이면 짝이 8×8 = 64개, 32가닥씩이면 32×32 = 1,024개. 가닥이 4배면 16배다. 부동소수점이냐 아니냐와 무관하게 정수 32비트여도 이 차이는 똑같이 난다.

둘째는 부동소수점의 덧셈이다. 곱셈이 아니라 덧셈이다. 부동소수점 곱셈은 가수끼리 곱하고 지수끼리 더하면 끝이라 오히려 단순하다. 덧셈은 자릿수가 다른 두 수를 더해야 해서 작은 쪽을 밀어서 맞추고, 더하고, 맨 앞 0을 세어 다시 밀고, 반올림하고, 지수를 다시 계산한다. 정수 덧셈은 이 중 한 단계다. 내가 "지수를 분석해서 몇 자리로 할지 확인한 후 작업한다"고 쓴 그 과정이 바로 이것인데, 그게 일어나는 곳이 덧셈기였다.

```
                   곱셈기        덧셈기        합계 대략
INT8 MAC           ≈ 3,000      ≈ 300         ≈ 3,000~4,000
FP32 MAC           ≈ 50,000     ≈ 10,000+     ≈ 60,000~80,000
                                              → 15~20배
```

같은 면적이면 INT8 MAC이 15~20배 들어간다. 덤으로 숫자 하나가 32비트에서 8비트가 되니 가중치 저장 공간도, 메모리에서 격자로 끌어오는 양도 4분의 1이다. 소형 NPU가 INT8만 남긴 이유다.

## 어떤 층은 많이 잃는다

층은 모델을 쌓은 단 하나하나다. 층 하나가 가중치 한 벌로 행렬곱 한 번이고, 층마다 가중치 범위가 다르니 양자화 눈금도 층마다 따로 정한다.

```
입력 영상 → [층 1] → [층 2] → [층 3] → ... → [층 50] → 점수
            가중치   가중치   가중치           가중치
            한 벌    한 벌    한 벌            한 벌
```

어떤 층은 가중치 대부분이 -0.1~0.1 안에 몰려 있는데 몇 개가 5.0 같은 튀는 값을 갖는다. 그러면 범위를 -5~5로 잡아야 하고 눈금 하나가 0.039가 된다. 대부분의 가중치가 들어 있는 0.1 안에 눈금이 두세 개뿐이라 0.03, 0.05, 0.07이 전부 같은 정수로 뭉개진다. 이 층의 정보가 거의 사라진다. 범위가 좁고 고른 층은 거의 안 잃고, 튀는 값이 있는 층은 많이 잃는다. "양자화하면 어떤 층이 문제"라는 말이 여기서 나온다. 그 층만 더 높은 정밀도로 두거나, 채널별로 눈금을 따로 잡는 식으로 푼다고 한다.

## INT4는 왜 정확히 두 배이고 왜 믿으면 안 되나

사양표에 "INT8 10 TOPS, INT4 20 TOPS"처럼 적힌다. 두 배인 이유는 8비트 곱셈기의 8×8 격자를 쪼개면 4×4 곱셈 여러 개를 동시에 돌릴 수 있기 때문이다. 실제 칩은 2개를 돌린다. 한 박자에 곱셈 2번이라 TOPS가 두 배, 메모리에서 끌어오는 가닥도 절반이라 공급도 두 배.

믿으면 안 되는 이유는 눈금 16개다. 대부분의 검출 모델은 INT4로 바꾸면 정확도가 쓸 수 없을 만큼 떨어진다. 그 20이 나오려면 모델의 모든 층이 눈금 16개로 버텨야 하는데 대부분 못 버틴다. 그러면 INT8로 올리게 되고 상한은 10이다. 거기서 입력 공급과 모양 문제로 또 깎인다. 비교할 때는 같은 정밀도 숫자로 맞춰서 본다. 한쪽이 INT4 숫자를 내세우면 반으로 나눠서 INT8로 환산한다.

## INT8은 MAC의 스펙인가

반은 맞다. INT8은 숫자를 담는 형식의 이름이고 그 형식이 세 군데에 걸린다.

```
INT8 = "숫자 하나를 8비트 정수로 담는다"는 형식

① 데이터 쪽   : 모델의 가중치와 입력을 INT8로 양자화했다
② 하드웨어 쪽 : 이 NPU의 MAC은 INT8 곱셈기로 만들어졌다     ← MAC의 스펙
③ 사양표 쪽   : 10 TOPS (INT8 기준으로 셌다)
```

②는 고정된 하드웨어다. 8가닥 곱셈기는 32비트 숫자를 받을 수 없다. 그래서 ①과 ②가 맞아야 돈다.

```
모델 형식    MAC 형식    결과
INT8    →   INT8 MAC    돈다
INT4    →   INT8 MAC    돈다 (쪼개서, 두 배 속도)
FP32    →   INT8 MAC    안 돈다 → 양자화해서 INT8로
INT8    →   FP32 MAC    돈다 (GPU처럼, 작은 숫자를 큰 회로에 넣어 낭비)
```

"이 모델을 이 NPU에 올리려면 양자화해야 한다"는 말이 나오는 이유가 이 표다. 학습이 끝난 모델은 FP32이고 소형 NPU의 MAC은 INT8이라서, 중간에 ①을 ②에 맞추는 작업이 반드시 끼어든다. 실무에서 그 말을 들을 때 뭘 하는 건지 이제 그림이 그려진다.

우연히 물어보다 걸린 부분이지만, 실무에서 들었던 단어라서 기록해 둔다.
