GPU와 NPU의 차이에 대해서 탐구하였다. 결론부터 쓰면, MAC끼리 결과를 메모리 안 거치고 옆 칸으로 바로 넘긴다. 그게 전부이긴 한데, 좀 더 상세하게 남겨본다. 

## 계산은 공짜, 이동이 전부

GPU에서 아직 남은 낭비가 하나 있다. 연산기가 곱셈을 끝내면 결과를 저장소에 쓰고, 다음 연산기가 그걸 다시 읽어 간다. 그런데 이 이동이 연산보다 비싸다.

이유는 거리다. 신호는 전선에 전하를 채워 전압을 올리는 것이라서, 전선이 길면 채울 전하가 많고 시간도 전력도 그만큼 든다. 1V로 올렸다 0V로 내리면 채운 전하는 접지로 버려진다. 배운 동적 전력이 바로 이것이다.

```
MAC → 옆 MAC        : 전선 수 μm       → 클록 1번 안에 도착
MAC → 캐시 → MAC    : 전선 수백 μm~mm  → 클록 수 번~수십 번
MAC → DRAM → MAC    : 전선 수 cm       → 클록 수백 번
```

전력도 같은 비율로 벌어진다. 곱셈 한 번을 1이라 하면 옆 MAC으로 넘기기가 1 안팎, 캐시 읽기가 수 배에서 수십 배, DRAM 읽기는 수백 배에서 천 배다. 곱셈 하려고 DRAM에서 숫자 하나 가져오면 계산보다 가져오는 데 전력을 수백 배 쓴다. 그래서 칩 설계자들이 "계산은 거의 공짜, 데이터 이동이 전부"라고 말한다고 한다. 어제 "NPU의 MAC이 노는 첫째 이유, 데이터가 안 와서"도 결국 이 거리 문제였다.

NPU와 TPU의 답은 가장 가까운 거리로만 움직이게 만드는 것이다.

```
GPU 방식                     TPU 방식 (systolic array)

MAC ──▶ 저장소 ──▶ MAC        MAC ──▶ MAC ──▶ MAC ──▶ MAC
MAC ──▶ 저장소 ──▶ MAC         │       │       │       │
MAC ──▶ 저장소 ──▶ MAC         ▼       ▼       ▼       ▼
                              MAC ──▶ MAC ──▶ MAC ──▶ MAC
(매번 저장소를 왕복)           (옆 칸으로 바로 전달)
```

systole는 심장 수축이다. 심장이 한 번 뛸 때마다 피가 한 칸 밀려가듯, 클록이 한 번 뛸 때마다 데이터가 MAC 한 칸씩 밀려간다.

## 임시 데이터는 어디에 있다가 가나

MAC에서 MAC으로 보낼 때 그 값이 어디에 들어 있다가 가는지가 궁금했다. 답은 레지스터였다. 어제 MAC 안에 누적값을 담는 레지스터가 있다고 했는데 그것과 같은 부품이다.

레지스터는 트랜지스터 몇 개를 고리로 엮어서 1이나 0을 붙잡아 두는 회로다. 비트 하나에 6~10개. 메모리와 다른 점은 주소를 찾을 필요가 없고 MAC 옆에 전선 하나로 직결되어 있다는 것이다. 그리고 성질이 하나 있다. 클록이 뛰는 순간에만 입력을 받아들이고, 그 외 시간에는 입력선이 뭘 하든 무시하고 잡은 값을 유지한다.

```
         클록 ──┐
                ▼
입력 ───▶ [레지스터] ───▶ 출력

클록이 뛰는 순간: 입력값을 복사해서 잡는다
그 외 시간      : 잡은 값을 출력에 계속 내보낸다
```

MAC 한 칸에는 레지스터가 둘 있다. 옆에서 들어온 숫자를 잡는 것과 곱하고 더한 결과를 잡는 것. 데이터는 이 레지스터에서 다음 MAC의 레지스터로 전선 한 가닥을 타고 넘어간다. 메모리로 가지 않는다.

칩 전체의 레지스터가 같은 클록을 듣는다. 클록이 뛰면 모든 레지스터가 동시에 자기 입력선 값을 잡는다. 그 입력선에는 왼쪽 칸의 출력이 걸려 있으니 한 박자에 모든 데이터가 한 칸씩 밀린다.

```
클록 1    [a]→[ ]→[ ]→[ ]
클록 2    [b]→[a]→[ ]→[ ]
클록 3    [c]→[b]→[a]→[ ]
클록 4    [d]→[c]→[b]→[a]
```

왜 a는 그럼 한 박자에 두 칸을 미끄러져 가지 않을까? 클록 2 순간에 세 번째 레지스터는 그냥 비어 있는 게 아니라 "빈 값을 받는 동작을 이미 끝냈다". 두 번째 레지스터가 a를 잡는 것과 같은 순간이라서, a가 도착했을 때 세 번째는 이미 이번 박자의 받기를 마친 상태다. 다음 클록까지 입력선을 쳐다보지 않으니 a는 거기서 한 박자 대기한다. 레지스터가 데이터를 한 칸씩 멈춰 세우고, 그 멈춘 시간 동안 곱셈기와 덧셈기가 일한다. 

## 2×2로 직접 돌려 보기

처음에 숫자 넣은 설명이 하나도 안 들어왔다. 격자가 가중치 숫자를 말하는 건지, MAC이 곱셈 아니면 덧셈 한 번만 하는 건지 헷갈렸다. 정리하면 격자는 MAC 4개를 2줄 × 2칸으로 놓은 것이고, 가중치는 그 MAC 안 레지스터에 하나씩 넣어 둔 숫자고, MAC 하나는 곱셈 1번 + 덧셈 1번을 한다.

```
입력    x1 = 2, x2 = 3
가중치  w11 = 1   w12 = 2
        w21 = 3   w22 = 4

y1 = x1·w11 + x2·w21 = (2×1) + (3×3) = 11
y2 = x1·w12 + x2·w22 = (2×2) + (3×4) = 16
```

타이밍은 빼고 누가 뭘 계산하는지부터. 곱셈 4개를 MAC 4개가 하나씩 맡는다. 규칙은 "자기 안에 든 가중치와 곱한다".

```
MAC(1,1):  2×1 + 0  = 2    ─┐ 아래로
MAC(2,1):  3×3 + 2  = 11   ◀┘        → y1

MAC(1,2):  2×2 + 0  = 4    ─┐ 아래로
MAC(2,2):  3×4 + 4  = 16   ◀┘        → y2
```

윗줄 MAC이 곱셈 결과를 아래로 내려 주면 아랫줄 MAC이 자기 곱셈 결과에 더한다. 그게 아랫줄의 덧셈이다. 윗줄은 위에 아무것도 없으니 0을 더한다. x1 = 2는 같은 행의 MAC 둘 다에 필요하니 왼쪽에서 넣으면 오른쩍으로 한 칸씩 전달되면서 둘 다에게 간다.

여기에 박자를 얹는다. 입력 x는 한 박자에 한 칸 오른쪽으로, MAC은 x와 위에서 온 중간합이 둘 다 도착한 박자에 계산해서 아래로.

```
박자 1
  x1=2 ──▶ [MAC(1,1)]   [MAC(1,2)]
            2×1+0 = 2
               │
           [MAC(2,1)]   [MAC(2,2)]

박자 2
           [MAC(1,1)]  x1=2 ──▶ [MAC(1,2)]
                                 2×2+0 = 4
                                    │
  x2=3 ──▶ [MAC(2,1)]           [MAC(2,2)]
           3×3+2 = 11 = y1

박자 3
           [MAC(2,1)]  x2=3 ──▶ [MAC(2,2)]
                                 3×4+4 = 16 = y2
```

x2를 박자 2에 넣는 이유는 MAC(2,1)에 x2와 "위에서 온 2"가 같은 박자에 와야 하기 때문이다. 행이 더 많으면 행마다 한 박자씩 늦춘다. 입력이 계단 모양으로 들어간다.

세 박자 동안 없었던 것: 명령 가져오기, 주소 계산, 메모리 왕복. 가중치는 처음에 깔았고 x는 왼쪽 끝에 박자 맞춰 밀어 넣기만 했다. 나머지는 레지스터와 클록이 알아서 했다. 어제 "제어기" 칸에 쓰던 트랜지스터가 거의 필요 없어지고, 그 자리를 MAC으로 채운다.

## 가중치를 MAC 안에 넣어 두는 게 실제인가

설명용인가 싶어서 물었는데 실제다. 데이터센터 TPU가 공개 논문에서 밝힌 구조가 이것이고, weight-stationary라는 이름도 있다. 왜 가중치를 고정하느냐는 신경망 계산의 성격에서 나온다. 합성곱 한 층에서 가중치는 한 벌이고 입력 픽셀은 수십만 개다. 같은 가중치를 모든 픽셀에 반복해서 곱한다. 바뀌지 않는 쪽을 MAC 안에 두고 바뀌는 쪽을 흘리는 게 이동량이 가장 적다.

모든 NPU가 가중치 고정은 아니라고 한다. 결과를 고정하고 입력과 가중치를 둘 다 흘리는 방식도 있다. 다만 "뭔가 하나는 MAC 안에 붙잡아 두고 나머지를 흘린다"는 원칙은 공통이다.

그럼 GPU는 매번 가중치를 바꿔서 전력을 더 먹는 거냐고 물었는데, 표현을 고쳐야 했다. GPU에는 격자가 없다. 가중치든 입력이든 매번 가져온다. 연산기 32개가 함께 쓰는 큰 레지스터 파일에서 x 읽고 w 읽고 곱하고 결과 쓰기. MAC 옆에 전선 하나로 붙은 레지스터와 이름은 비슷한데, 수만 칸을 주소로 골라 읽는 저장소라서 읽기 한 번이 곱셈 한 번보다 전력을 더 먹는다.

```
                  곱셈 한 번당 이동
TPU 격자         x 옆칸에서 받기, 결과 아래로     (가까운 거리 2번, w는 이동 없음)
GPU              x 읽기, w 읽기, 결과 쓰기         (중간 거리 3번)
```

최근 GPU는 이걸 알고 연산기 옆에 4×4나 8×8짜리 작은 행렬 유닛을 붙였다고 한다. TPU 아이디어를 조금 빌려 온 것인데 격자가 수십 배 작고 주변 구조는 그대로라서 전력은 여전히 NPU나 TPU가 유리하다.

## 컨베이어: 다음 묶음은 언제 넣나

첫 묶음이 박자 3에 끝난다. 다음 묶음은 그때까지 기다려야 하나. MAC(1,1)은 박자 1에 일을 끝내고 비어 있으니 박자 2에 바로 넣을 수 있다. 맞았다.

```
         박자1    박자2    박자3    박자4    박자5
묶음A   (1,1)    (1,2)    (2,2)
                 (2,1)
묶음B            (1,1)    (1,2)    (2,2)
                          (2,1)
묶음C                     (1,1)    (1,2)    (2,2)
                                   (2,1)
```

박자마다 새 묶음이 들어가고 박자 3부터는 박자마다 결과가 하나씩 떨어진다. 처음 2박자는 격자가 채워지는 시간이고 그 뒤로는 모든 MAC이 매 박자 일한다. 어제 TOPS 공식이 "MAC 개수 × 클록 × 2"였던 이유가 이것이다.

그리고 이게 어제 "MAC이 노는 이유"의 실체다. 컨베이어가 꽉 차려면 박자마다 왼쪽 끝에 새 입력이 들어와야 한다. 메모리가 한 박자에 입력 한 줄을 못 대 주면 그 박자에 격자 전체가 빈다. 격자가 수천 칸이면 빈 박자 하나에 수천 번의 연산 기회가 사라진다. MAC을 늘려도 입력을 대 주는 속도가 안 따라오면 쓸모가 없다. 그래서 큰 NPU들은 격자 옆에 수 MB짜리 메모리를 붙여 둔다.

## 격자보다 가중치가 크면

가중치 행이 3개인데 격자 행이 2개면 어떻게 되나. "한 묶음 계산하고 가중치를 싹 바꿔서 마무리한 뒤 다음 묶음" 아닐까 했는데 순서가 거꾸로였다. 그러면 묶음이 백만 개면 교체도 백만 번이라 가중치 고정의 이점이 사라진다. 실제로는 가중치를 한 번 깔고 모든 묶음을 다 흘린 뒤에 교체한다.

```
1차 통과: 1~2행 가중치를 깐다. 묶음 전부를 흘린다.
          나오는 값 = x1·w1 + x2·w2  → 메모리에 저장

가중치 교체 (한 번)

2차 통과: 3행 가중치를 깐다. 나머지 1행은 빈 칸.
          묶음 전부를 다시 흘린다. 1차 결과를 꺼내 더한다 → 최종 y
```

손해가 두 군데 난다. 2차 통과 때 격자 절반이 놀아서 전체 75%. 이게 어제 말한 "모양이 안 맞아서 노는 MAC"이다. 실제 격자는 64×64나 256×256이라서 어떤 층의 채널 수가 70이면 64 + 6으로 쪼개져 두 번째 통과가 거의 빈다. 그리고 1차 중간 결과를 메모리에 쓰고 2차에 다시 읽어야 하니 아까 비싸다고 한 이동이 묶음마다 추가된다.

같은 TOPS라도 격자 모양이 다르면 같은 모델에서 실제 속도가 다르다는 뜻이다. 사양표 숫자만 보면 안 되는 이유가 하나 더 늘었다.

## 오늘까지 정리

| | 제어기 | 연산기 | 데이터 이동 |
|---|---|---|---|
| CPU | 코어마다 하나, 매우 똑똑함 | 코어당 몇 개 | 캐시 중심 |
| GPU | 32개가 하나 공유 | 수천 개 | 큰 레지스터 파일 왕복 |
| NPU/TPU | 거의 없음, 순서 밀어 주는 정도 | MAC 격자 수천~수만 | 옆 칸으로 직접, 가중치는 고정 |

남은 것은 NPU와 TPU의 차이, 격자 옆에 붙는 메모리(SRAM과 DRAM, 대역폭), 그리고 이걸 사양표 읽는 눈으로 바꾸는 실무 판단이다.
